# 🌍 Travel Planner — Android Application

**TravelPlanner** — це мобільний додаток для Android, розроблений для зручного планування подорожей, управління бюджетом та організації списку локацій для відвідування. Проєкт пропонує реактивний інтерфейс для відстеження маршрутів та збереження пам'ятних місць.

---

## Технологічний стек

Проєкт реалізовано з використанням набору інструментів native-розробки:

| Рівень | Технологія |
| :--- | :--- |
| **Мова** | Kotlin |
| **Інтерфейс** | Jetpack Compose + Material Design 3 |
| **Навігація** | Jetpack Navigation Compose |
| **Локальна БД** | Room (SQLite) |
| **Архітектура** | MVVM + Repository Pattern + StateFlow |

## 🗂️ Моделі даних

Логіка додатка базується на трьох ключових сутностях зі зв'язками:

1. **User (Користувач)**: Профіль мандрівника (ID, ім'я, email).
2. **Trip (Подорож)**: Основна сутність, щр містить дані про подорож (назва, бюджет, дата, статус завершення).
3. **Place (Місце)**: Конкретна локація всередині подорожі (назва, статус відвідування).

### Реалізовані операції (CRUD):
1.  **Create**: Збереження нових подорожей та місць.
2.  **Read (List)**: Отримання списку всіх подорожей через `Flow` (реактивне оновлення UI).
3.  **Read (Object)**: Отримання детальної інформації про конкретну подорож за її ID.
4.  **Delete**: Видалення подорожі та автоматичне очищення пов'язаних місць.

## 🔄 Стратегія синхронізації: Offline-First

У додатку реалізовано стратегію **Offline-First**, оскільки доступ до планів подорожей має бути миттєвим навіть у літаку, горах чи в умовах роумінгу.

**Як це працює:**
*   **Читання:** Дані завжди завантажуються з локальної бази Room.
*   **Запис:** Будь-яка зміна спочатку зберігається локально зі статусом `SyncStatus.PENDING`.
*   **Синхронізація:** Додаток ініціює запит до API. При успішній відповіді запис отримує статус `SYNCED`. У разі помилки мережі статус стає `ERROR`, що дозволяє повторити спробу пізніше.

## 🌐 REST API Contract

Взаємодія з сервером побудована за принципом **REST API**. На даному етапі реалізовано сервісний шар `MockTripApiService`, який імітує мережеві запити з затримкою.

| Метод | Шлях | Body / Params                                 | Що повертає | Опис |
| :--- | :--- |:----------------------------------------------| :--- | :--- |
| **GET** | `/trips` | —                                             | `List<TripDto>` | Отримати список усіх подорожей користувача |
| **GET** | `/trips/{id}` | **Path** `id`                                 | `TripDto` | Отримати деталі однієї подорожі |
| **POST** | `/trips` | **Body:** `title`, `budget`, `date`, `userId` | `TripDto` (Created) | Створити нову подорож |
| **DELETE** | `/trips/{id}` | **Path** `id`                          | `204 No Content` | Видалити подорож та всі її локації |
| **POST** | `/trips/{id}/places` | **Path:** `id`, **Body:** `name`, `isVisited` | `PlaceDto` | Додати локацію до подорожі |
| **GET** | `/profile` | —                                             | `UserDto` | Отримати дані поточного профілю |
